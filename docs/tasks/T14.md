# T14 · 문서·제출 점검

상태: 완료

## 목표와 제외
실행·구조·DB·규칙·시연·검증·Git 이력을 공개 저장소에서 확인할 수 있게 정리한다. 제출 메일·문자 발송은 포함하지 않는다.

## 선행 및 입력
T00~T13, T15 완료 기록과 실제 Git 이력. docs/spec.md·contracts.md, package.json 실행 명령, src/server/tests, artifacts/packaged 검증 결과.

## 수정 범위와 사용자 동작
- README: 설치·샘플 계정·시연 초기화·일반 서버·패키지 실행, 구조/DB와 선택 이유, 컨벤션, 제약.
- docs/demo.md·qa.md: 일관된 시연 순서와 필수 FR별 검증 근거, 실제 앱 화면.
- docs/tasks/: 각 Task 선행·파일 범위·완료·인계 기록.
- scripts/export-history.mjs, docs/history.json·md: 실제 SHA·부모·브랜치·병합 데이터 생성.
- .github/workflows/ci.yml: Node 24에서 설치·포맷·테스트·타입/빌드 자동 검사.
- 새 사용자가 README 순서대로 설치·실행하고 반차·출퇴근·팀 현황을 시연한다.

## 완료 조건과 검증
- 최신 명세·계약·시드·UI의 연차/반차 규칙 일치.
- 서버 테스트 24개 통과, 타입 검사·빌드·포맷 검사 통과, macOS 실제 패키지 검증은 T13 참조.
- Markdown의 저장소 내 링크·이미지 존재, 공개 원격 저장소에 모든 Task 브랜치·커밋·병합 게시.
- Git 스냅샷은 기준 HEAD를 명시한다. 문서 자신을 저장하는 커밋은 다음 추출에서 포함되므로 재귀적으로 갱신하지 않는다.

## 인계
- 변경: 제출 문서, 실행·시연 안내, FR 대응표, Task 인계와 Git 데이터, CI.
- 검증: 로컬 자동 검사 및 실제 Electron/패키징 결과는 docs/qa.md. 원격 CI의 실행 결과는 저장소 Actions에서 확인.
- 남은 문제: 공휴일 지원 2026년 한정, 단일 서버 프로세스, 서버 재시작 시 재로그인. 다른 OS·코드 서명·공증 미검증. 승인/PDF/월 정산은 계획상 제외.
- 다음 Task 영향: 이후 기능은 새 브랜치에서 명세·계약을 먼저 변경하고 검증 후 병합한다.
