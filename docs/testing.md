# 기능 테스트와 버그 점검

검증일: **2026-11-03**. 대상: T17 팀원 연차·반차 승인과 T18 버그 수정.

**결과: 서버 자동 테스트 32개 통과, 실제 Electron 시나리오 16개 묶음 통과, 렌더러 오류 0건.** TypeScript/Vue 빌드와 포맷 검사도 통과했다. 검증 환경은 macOS arm64, Node 24.22.2, Electron 45.2.1이다.

이번 UI 검증은 빌드된 Vue 파일을 실제 Electron 창에서 실행했다. 사용 중인 개발 서버와 겹치지 않도록 테스트 API는 3101 포트·임시 SQLite로 분리했다. 기본 창과 최소 860×680 창의 승인 목록·검토 폼을 확인했으며, 주요 버튼 잘림이나 가로 넘침은 발견하지 않았다. 서버/앱 재시작도 시나리오에 포함했다.

리드 승인은 **팀원 연차·오전/오후 반차**에 적용한다. 리드 본인 휴가·재택·휴일 근무는 자동 확정한다.

## 실행 명령

Node 24 환경에서 실행한다. UI 테스트는 3000 포트가 비어 있어야 하며 임시 SQLite를 사용한다.

```sh
npm test
npm run build
npm run format:check
npm run test:ui
```

Node 버전이 다르면 각 명령 앞에 `npx --yes --package=node@24 --package=npm@10.9.4 --`를 붙인다.

## 발견한 문제와 수정

| ID | 확인 방법 / 문제 | 수정 | 확인 결과 |
|---|---|---|---|
| B01 | Electron 재현: 오늘 출근해 근무 중인데 내 근태에 ‘퇴근 미기록’ 표시 | 오늘 열린 근태는 ‘근무 중’, 이전 날짜만 ‘퇴근 미기록’으로 구분 | 출근 후 내 근태 행에서 정상 표시 확인 |
| B02 | Electron 재현: 신청 기한 조회 중 날짜를 지우면 로딩 문구가 계속 남음 | 날짜를 비울 때 로딩 해제, 이전 조회 결과 무시 | 지연 응답 중 날짜 삭제 후 로딩 해제 확인 |
| B03 | Electron 재현: 연결 오류에서 ‘로그인으로’를 눌러도 이전 세션 토큰이 저장소에 남음 | 세션 초기화 시 토큰 제거, 초기 로그인 복원 완료 때 경로 권한 재검사 | 로그인 이동·네트워크 복구·새로고침 후 로그인 화면 유지 |
| B04 | 코드 점검: 오전/오후 반차에도 07시·10시·16시 일반 근무 안내 | 승인된 근무 종류에 맞춰 안내 분기 | 오전 12:30 출근, 오후 11:30 퇴근 안내 확인 |
| B05 | 코드 점검: 팀 날짜 조회의 이전 응답이 최신 결과를 덮을 수 있음 | 마지막 요청에 해당하는 응답만 반영 | 13일 요청을 지연시키고 12일 선택 후 응답 순서를 뒤집어도 12일 유지 |

추가 보완: 휴가 예약·반려 반환을 원장에 구분 표시하고, 승인 상태 열을 내 신청 표 앞쪽에 배치했다. 승인 검토창은 최소 창에서 하단 버튼이 보이도록 가운데 정렬한다.

## 승인·반려 수동 재현

시연 DB를 초기화하려면 실행 중인 앱과 서버를 먼저 종료한 뒤 `npm run demo:reset`, `npm run dev`를 실행한다. 아래 초기 시각은 2026-03-12 09:00이다.

1. `kim` / `demo1234`로 로그인한다. 연차 잔여 2일을 확인한다.
2. 신청에서 3월 13일 연차 1일, 3월 16일 오전 반차, 3월 17일 오후 반차를 **승인 요청**한다. 모두 승인 대기, 신청 가능 잔여 0일이 된다.
3. 로그아웃 후 `lead`로 로그인하고 **휴가 승인** 메뉴를 연다. 날짜를 따로 고르지 않아도 대기 3건이 보인다.
4. 13일과 17일 신청을 검토·승인한다. 16일은 반려를 누르면 빈 사유 오류가 나오며, 사유를 입력하고 반려하면 완료된다.
5. `kim`으로 돌아가면 승인 2건·반려 1건과 처리 사유, 반환된 잔여 0.5일이 보인다. 16일 오전 반차를 다시 신청하면 과거 반려 기록과 새 대기 기록이 모두 남는다.
6. 리드가 새 신청을 승인한다. 승인된 일정은 팀 보드와 오늘 화면에 적용된다.
7. 리드 시각을 3월 16일 12:30으로 변경한다. 김근태는 오전 반차 안내를 보고 출근할 수 있다. 16:30 퇴근이면 정상 4시간이다.

승인 전 출근은 일반 근무로 처리된다. 이미 출근한 날에는 이후 휴가 승인을 막는다. 사용일이 지난 대기 신청은 승인할 수 없고 리드가 반려해 예약을 해제한다.

## 범위와 한계

- 공휴일은 2026년, 단일 서버 프로세스, 같은 날 출퇴근을 지원한다.
- 취소·수정, 재택/휴일 승인, 다중 리드 결재 단계는 이번 범위에 포함하지 않는다.
- 기존 확정 신청은 승인 상태로 이관한다. 과거 근무시간·차감 기록을 다시 계산하지 않는다.
- Windows/Linux의 데스크톱 UI, 배포 서명·공증은 검증하지 않았다. 기존 T13의 패키지 실행 결과와 이번 빌드된 렌더러의 Electron 검증을 구분한다.
- GitHub CI는 서버 테스트·포맷·빌드를 실행한다. macOS Electron 화면 검증 결과는 위 JSON과 캡처를 참고한다.
